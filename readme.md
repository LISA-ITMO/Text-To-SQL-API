# Text-To-SQL-API
___

### **Описание проекта**
___
**Text-to-SQL-API** - это проект на основе локальных LLM и RAG для решения задачи перевода естественного языка в команды SQL и применения дополнительных функций и RAG для получения контекста. Проект создано в формате API для применения в иных приложениях и дополнении своим функционалом по мере необходимости.

**LLM** - были выбраны 2 варианта. Наиболее быстрый (первый) и наиболее оптимальный по качеству инференса (второй). Ссылки для скачивания с huggingface представлены ниже:
- [Llama3-2-3B-Instruct-text-to-sql-20K_GGUF_Q4_K_M](https://huggingface.co/Tvisterious/Llama3-2-3B-Instruct-text-to-sql-20K_GGUF_Q4_K_M)
- [llama-3-sqlcoder-8b-Q4_K_M-GGUF](https://huggingface.co/colabbear/llama-3-sqlcoder-8b-Q4_K_M-GGUF)

*(В РАЗРАБОТКЕ)* **RAG** - Сейчас функционал активно дорабатывается. В проекте содержится RAG для работы с определенной базой данных, так что использовать его в своей предметной области пока не получится. *(В РАЗРАБОТКЕ)*

### **Структура и архитектура**
___
- `main.py` — точка входа работы программы. Содержит включения роутов и строку с указанием пути к LLM модели.
- `/app/DAOs/` — папка с определением функций LLM-модели и её tools, которые используются непосредственно при работе с API.
- `/app/models/` — папка с функциями моделей эмбеддинга для RAG.
- `/app/routers/` — папка с определением эндпоинтов/ручек для работы с API.
- `/app/services/` — папка с дополнительными функциями для работы с БД, RAG и LLM.
- `/app/upgo_rag_system/` - дополнительный функционал для RAG.
- `/app/schemas.py` - pydantic-модели для форматированного ввода данных при вызове эндпоинта/ручки.
- `/gguf_model/` - (НУЖНО САМОСТОЯТЕЛЬНО СОЗДАТЬ) папка с локальными LLM.
- `.gitignore`,`requirements`,`LICENSE` - вспомогательные файлы git и развертывания проекта.

### **Процесс работы**
___
Рабочие эндпоинты/ручки, которые могут быть использованы на данный момент:

- `/LLM/getllmsqlanswer` - требует промпт и контекст (вручную). Выводит SQL по предоставленным данным.

- `/LLM/getllmanswer` - требует промпт. Выводит ответ от LLM.

- `/LLM/getllmanswerwithtoolandchain` - требует промпт и bool execute_sql. Выводит SQL (или сразу выполняет его в БД) на основании контекста из локальной БД (подключение производится по кредам из '.env').

- `/LLM/getllmanswerwithrag` - генерация SQL по контексту из RAG (В разработке). 

- `/tool/getalltablesinfo` - получить контекст о таблицах и их полях из БД (подключение производится по кредам из '.env').

### **Установка и запуск**
___
1) Скачайте или клонируйте проект в удобную директорию.
2) В корне проекта (там, где находится main.py) создайте папку 'gguf_model'. 
3) Скачайте наиболее подходящую LLM (по ссылкам выше или другую gguf-модель) и переместите в данную папку.
4) В файле main.py поменяйте путь к нужной LLM в аргументах функции 'load_model' и её название на необходимое.
5) Перед запуском необходимо установить зависимости. Откройте проект в IDE и выполните команду 'pip install -r -requirements.txt'.
6) Для доступа к собственной локальной БД в корневой папке также создайте файл '.env' и заполните следующие поля своими данными: DB_USER, DB_PASSWORD, DB_HOST, DB_PORT, DB_NAME.
7) Для запуска выполните команду 'uvicorn main:app --reload'. Она поднимает локальный сервер на порту 8000.
